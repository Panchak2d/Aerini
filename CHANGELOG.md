## [Unreleased]

### Added
- Image Generation: a **Model** field for Nano Banana (`gemini-2.5-flash-image`, the default, `gemini-nano-banana-2.1` or `gemini-3.1-flash-lite-image`). Google shuts the default down on March 15 2027, and a run on it now logs a warning. Google's documentation does not confirm the two newer models work through the request this node sends, so the default is unchanged. See `docs/guide/nodes.md#image-generation`
- Discord: an **Allow @everyone mentions** option (`allow_everyone_mentions`, off by default) lets `@everyone` and `@here` in Content ping the channel; the webhook's channel permissions can still block it. See `docs/guide/nodes.md#discord`
- SendGrid: a **From Name** field sets the sender's display name; a name with a line break or over 200 characters fails with `INVALID_FROM_NAME`. See `docs/guide/nodes.md#sendgrid`
- Google Sheets: a **Value Input** option on `append_row` (`RAW`, the default, or `USER_ENTERED`) lets Sheets parse formulas, dates and numbers. Do not use `USER_ENTERED` with data you do not control. See `docs/guide/nodes.md#google-sheets`
- S3 Storage: **Provider**, **Content Encoding** and **Method** accept any letter case (`R2`, `Base64`, `put`); other values still fail with their named errors, and an unknown **Operation** is now reported before the connection settings are checked. See `docs/guide/nodes.md#s3-storage`
- S3 Storage: `list` takes **Max Objects** (`max_objects`, 1 to 10000, default 10000) and a **Delimiter** (`delimiter`, usually `/`), and the output adds `common_prefixes` for the folder-like groups; a value outside the range fails with `INVALID_CONFIG`. See `docs/guide/nodes.md#s3-storage`
- S3 Storage: a `presign_url` upload link (`PUT`) can sign in a **Content Type** and a **Content Length** (up to 5 GiB), and the output has a `headers` object with the headers the uploader must send. See `docs/guide/nodes.md#s3-storage`
- S3 Storage: `presign_url` takes a **Method** (`GET`, the default, or `PUT`), so it can make an upload link as well as a download link; the output includes `method`. See `docs/guide/nodes.md#s3-storage`
- If / Condition: structured **Left Value**, **Operator** and **Right Value** fields. Each side is compared whole, so a value that contains `>`, `=` or ` contains ` is no longer misread, which the single **Condition** string could not guarantee. When Left Value or Right Value has text the structured fields are used; otherwise Condition is, so existing workflows are unchanged. See `docs/guide/nodes.md#if--condition`
- Docs: a new section on how Loop and Merge behave together (iteration order, branch gating, what `all_results` holds, failure routing, stale outputs). See `docs/guide/nodes.md#how-loop-and-merge-behave-together`
- Transform: a mapping with `from` set to `$` copies the whole source output into its `to` key, next to ordinary pointer mappings. Existing mappings are unaffected, and a key literally named `$` is still reachable as `/$`. See `docs/guide/nodes.md#transform-data`
- Canvas (desktop): **Undo** and **Redo** buttons in the toolbar, with a tooltip naming the step each one will undo or redo, and a status-bar message after each. Renaming a node, enabling or disabling it, choosing its saved credential, and changing its settings can now be undone (typing in one field is a single step), where before only adding, deleting, moving, and wiring could. `Ctrl+Shift+Z` now works for Redo on every keyboard (Caps Lock, non-Latin layouts). See [Keyboard shortcuts](docs/guide/keyboard-shortcuts.md)
- AI Memory: a conversation can now remember the files shared in it, so an AI node keeps seeing them on later messages instead of only on the message that carried them. Set **Files** (e.g. `{{Webhook.output.files}}`) on `append` or `write` to store files with a message, and turn on **Include Files** to get them back as a `files` output you can wire to an AI node's Files port; a new `forget_files` operation deletes a session's files and keeps its messages. Both are off by default, so existing workflows behave as before. Limits: png, jpeg, webp, gif, pdf, txt and md only; 3 MiB per file; 20 files and 32 MiB kept per session (**Max Stored Files**); at most 5 files (**Max Files**, up to 20) and 12 MiB returned per read, drawn from messages inside **Max Messages**. Files are kept or dropped whole, oldest first, and identical files are stored once. `clear` (including the Chat panel's Clear and session delete), `write`, and pruning past **Max Stored** now delete the files with their messages. Remembered files are stored unencrypted in `ai_memory.db`, are sent to the AI provider again on every run that wires them in, and are copied into run history with the node's output. Adds an `ai_memory_files` table, created on first use, to `ai_memory.db`; existing data is untouched and no migration runs. See [Nodes Reference](docs/guide/nodes.md#remembering-files) and [Chat Panel](docs/guide/chat-panel.md#attachments)
- Chat panel: a banner above the messages now flags wiring that would make replies fail or ignore attached files — files that no node reads, or a node that uses another node's output without running after it — and fixes the common cases in one click (**Connect to** an AI node, **Connect them**); a running workflow picks the fix up on its next run, with no restart. It replaces the short-lived "no node reads them" notice shown after sending files. Connections made this way can be undone with `Ctrl+Z`.
- Desktop: in-app updates. **Settings → About → Updates → Check for Updates** shows a newer version, and **Install and restart** downloads it, verifies its signature, installs it, and restarts, with a progress bar and a Cancel button. Updating is still click-only (nothing is checked in the background), Aerini asks before stopping running workflows or when changes may be unsaved, and where an in-app install isn't possible it links to the release page instead. Aerini 0.4.1 and earlier can't update themselves, so install the first release that includes this by hand once. See [Updating](docs/operations/updating.md#desktop-app) and [Security](docs/guide/security.md#updates-and-the-network)
- `aerini-server` (`api`) and the desktop app: `scheduler-status` events now include a `trigger_type` field (`interval`, `cron`, `once`, `webhook`, `manual`, or `plugin`), so a client can tell what kind of trigger a job has without reading its stored trigger; the field is additive and existing clients are unaffected. See [Events](docs/operations/server-api-reference.md#events-sse)
- Chat panel: files attached to a sent message now appear as filename chips in that message, and are saved with the session, so they are still shown after switching sessions or restarting the app. Adds a nullable `attachments_json` column to the local chat-message table (local database version 9, unrelated to a workflow file's `schema_version`; existing messages are unaffected); see `docs/guide/chat-panel.md#attachments`
- Webhook: a request body with an `attachments` array (as the desktop Chat panel sends when files are attached) is now also exposed as a top-level `files` output, so `{{Webhook.output.files}}` can be wired to a Files input such as AI Prompt's; `body.attachments` is unchanged, and `files` is omitted when the body has no `attachments` array. Applies to both ad-hoc Run and background (scheduler-driven) runs; see `docs/guide/nodes.md#webhook`
- Chat panel: you can send attachments without any text (the message is posted to the webhook as an empty string), and clicking a sent file chip opens an image full-size or downloads any other file; see `docs/guide/chat-panel.md#attachments`
- Execution Transcript: clicking a log line that's tied to a specific node now selects that node on the canvas, the same way clicking a run-history entry does; keyboard-accessible via Enter/Space when the line is focused
- `aerini-server`: a prebuilt container image is now published to GHCR (`ghcr.io/panchak2d/aerini-server`) on every tagged release, tagged with the release version and `latest`; `docker pull` replaces cloning the repo and building the image yourself as the fastest way to get a working binary. See [Server Deployment](docs/operations/server-deploy.md#getting-the-aerini-server-binary)
- Plugins: a trigger plugin can now export `metadata` (icon, author, version) by targeting the new `aerini-node-with-trigger-and-metadata` world; plugins built against `aerini-node-with-trigger` load unchanged. Trigger-capable plugins are listed under **Triggers** in the node palette, next to Schedule and Webhook, with their Plugin badge; see `docs/development/plugin-authoring.md#trigger-plugins`
- Plugins: a trigger plugin can now report when its next event is due, so the Background Runs panel shows "next in Ns" for it, by targeting the new `aerini-node-with-trigger-and-next-fire` world and calling its `trigger-schedule` import; reported times are validated and never affect scheduling. Plugins built against any earlier world load unchanged and keep showing "running", and the bundled heartbeat example now reports its next beat. See `docs/development/plugin-authoring.md#showing-a-countdown-to-the-next-event`
- HTTP Request: `HEAD` and `OPTIONS` are now available in **Method**, for checking a URL's headers (`content-length`, `etag`, `allow`) without downloading it. A `HEAD` result has an empty `body`; see `docs/guide/nodes.md#http-request`
- Notion: **Database ID** also accepts a link to the database pasted from `notion.so` or `notion.site`, and a new **Data Source ID** (`data_source_id`) field lets `create_page` add to one data source of a database that has several; that call is sent with Notion API version `2025-09-03`, all others stay on `2022-06-28`. See `docs/guide/nodes.md#notion`
- Notion: a **Title Property** field names the database's title property (default `Name`), so create and update work on databases whose title column has another name. See `docs/guide/nodes.md#notion`

### Changed
- Canvas (desktop): a field named `values` or `properties` on a plugin node, or on any node other than Google Sheets and Notion, is now a single-line box like any other text field, where before it was always multi-line. A node opts a field into the multi-line box with `"x-aerini-multiline": true` in its schema. See `docs/development/node-authoring.md`
- **Breaking** for S3 Storage `presign_url` (all runs, including `aerini-server` and `api`): a Content Type or Content Length set on a `GET` link now fails with `PRESIGN_PUT_ONLY`; before, it was ignored. Clear them, or use `PUT`. A download that breaks off partway now shows the underlying cause in its error. See `docs/guide/nodes.md#s3-storage`
- **Breaking** for Send Email (all runs, including `aerini-server` and `api`): the send is now driven step by step, so the node knows whether the message body was sent. Every failure before the body (a connection that fails or times out, a failed or temporary-refused login, a `4xx` reply to the sender, a recipient or `DATA`, a server that stops answering for 30 seconds) is now a recoverable `SMTP_ERROR` that a retry policy retries, because no message data had been sent; before, only a refused connection was. Permanent replies, and every failure at or after the body, behave as before (`SMTP_ERROR` or `SMTP_DELIVERY_UNCERTAIN`, never retried). The extra probe connection to the server before the SMTP handshake is gone, and when a host has several addresses the next is tried after a failed connection. See `docs/guide/nodes.md#send-email`
- **Breaking** for Text Splitter in `sentences` mode (all runs, including `aerini-server` and `api`): a short built-in list of abbreviations (`Mr.`, `Mrs.`, `Dr.`, `Prof.`, `e.g.`, `i.e.`, `vs.`, an initial such as `J. K. Rowling`, and others) no longer ends a sentence, and Arabic, Armenian, Devanagari, Ethiopic, Khmer and Myanmar sentence marks and `‼ ⁇ ⁈ ⁉` now do, so chunk counts can change. See `docs/guide/nodes.md#text-splitter`
- **Breaking** for Image Generation with Nano Banana (all runs, including `aerini-server` and `api`): an HTTP 403 is no longer always `INVALID_API_KEY`. It is now `API_KEY_LEAKED`, `PROJECT_DENIED`, `API_KEY_RESTRICTED` or `PERMISSION_DENIED` by Google's message, and a location Google does not serve is `REGION_NOT_SUPPORTED`; all are unrecoverable, carry Google's text and stop an `n` loop. See `docs/guide/nodes.md#image-generation`
- **Breaking** for Image Generation (all runs, including `aerini-server` and `api`): an `n` loop now also stops after a timeout, poll failure, connection failure or blocked prompt, where Flux and GPT Image went on to request, and pay for, the next image; the log says why it stopped. A download whose `Content-Type` is text, JSON or XML now fails with `DOWNLOAD_ERROR`, and a body that breaks off mid-download is tried again. See `docs/guide/nodes.md#image-generation`
- **Breaking** for Desktop Notification (all runs, including `aerini-server` and `api`): a Title or Body that is not text now fails with `INVALID_TITLE` or `INVALID_BODY`; before, a non-text Body was sent empty. On Linux the Title is now escaped like the Body (`<`, `>`, `&`), so workflow data cannot inject markup through it. See `docs/guide/nodes.md#desktop-notification`
- **Breaking** for Image Generation with Automatic1111 and Flux Pro (all runs, including `aerini-server` and `api`): `a1111` Width and Height are now rounded to the nearest multiple of 8 before the call (the server otherwise cut the image to a multiple of 8 without saying so), and the log notes an adjustment. `flux_pro` sizes are now rounded to the nearest 32, as documented; before, they were rounded down. See `docs/guide/nodes.md#image-generation`
- **Breaking** for Image Generation with Flux (all runs, including `aerini-server` and `api`): a job BFL reports as `Task not found` five polls in a row now fails with `TASK_NOT_FOUND` (not retried, naming the job id and polling URL) instead of waiting for the 120 second `TIMEOUT`. See `docs/guide/nodes.md#image-generation`
- **Breaking** for Text Splitter in `sentences` mode (all runs, including `aerini-server` and `api`): a `.`, `!` or `?` directly followed by a Chinese, Japanese or Korean character now ends a sentence, so chunk counts can change. In `paragraphs` mode a bare CR line ending now separates lines. A split over 100,000 chunks now stops early and its `TOO_MANY_CHUNKS` message says "more than 100000". See `docs/guide/nodes.md#text-splitter`
- **Breaking** for Image Generation with ComfyUI (all runs, including `aerini-server` and `api`): when the node gives up (`TIMEOUT`, `POLL_FAILED`, `POLL_REJECTED`) or the run is cancelled, it now cancels the job on the ComfyUI server (`GET /queue`, then `POST /interrupt` with the job's id, or `POST /queue` to delete a queued job). Before, the job kept running there. A running job is interrupted only after the queue confirms it is ours. The timeout message reports what happened. See `docs/guide/nodes.md#image-generation`
- **Breaking** for Google Sheets and Notion (all runs, including `aerini-server` and `api`): a missing or blank **Action** now fails with `MISSING_ACTION`. Before, Sheets read the range and Notion created a page, so a config that lost its action ran the wrong operation. Notion Update Page now retries a timeout, since repeating it changes nothing further. See `docs/guide/nodes.md`
- **Breaking** for retry policies on nodes that send or create (all runs, including `aerini-server` and `api`): a request that times out is no longer retried for Slack, Telegram, Discord, SendGrid, GitHub, Notion, Google Sheets Append Row, the image-generation nodes, or an HTTP Request using `POST` or `PATCH`, because the provider may already have sent the message or created the record, and a retry would repeat it. A connection that could not be made is still retried. AI Prompt, AI Agent, Stripe, Google Sheets Get Values and HTTP Request with `GET`, `HEAD`, `OPTIONS`, `PUT` or `DELETE` still retry a timeout. Retry by hand when you know the first attempt did nothing. See [Nodes Reference](docs/guide/nodes.md)
- **Breaking** for Discord (all runs, including `aerini-server` and `api`): `@everyone` and `@here` in Content no longer ping anyone; user and role mentions still do. The Webhook URL must now be exactly `https://discord.com/api/webhooks/<id>/<token>` (or `discordapp.com`, with an optional `/api/vN/`); a URL with another host, a port, a login or extra path segments fails with `INVALID_WEBHOOK_URL`, and surrounding spaces are ignored. See `docs/guide/nodes.md#discord`
- **Breaking** for SendGrid (all runs, including `aerini-server` and `api`): addresses are checked before sending and an invalid one fails with `INVALID_TO_EMAIL` or `INVALID_FROM_EMAIL`. A comma or semicolon list in To Email now sends to each address as a separate copy (up to 1000, duplicates once), where it was one bad address. An empty body fails with `MISSING_BODY` and a body that is not text with `INVALID_BODY`. See `docs/guide/nodes.md#sendgrid`
- **Breaking** for Slack: Text over 40,000 characters fails with `TEXT_TOO_LONG` instead of being cut short by Slack. A `missing_scope` failure now names the scopes Slack reports. See `docs/guide/nodes.md#slack`
- **Breaking** for Send Email (all runs, including `aerini-server` and `api`): a failed send is no longer always retried when a retry policy is on. A permanent reply (`550`, `535`) and a temporary one (`4xx`) fail with `SMTP_ERROR` and are never retried, because a `4xx` can answer the end of the message body and a retry could send the email twice; only a refused connection is retried. A connection that times out or drops after the message may have reached the server fails with the new `SMTP_DELIVERY_UNCERTAIN` and is never retried, and a send that gets no answer for 120 seconds is stopped with it (before, the node waited without a limit). A missing or null `subject` now fails with `MISSING_SUBJECT`, where it was sent as `(no subject)`; a missing or null `body` fails with `MISSING_BODY` and one that is not text with `INVALID_BODY`, where it was sent empty. A `subject` that is not text is `INVALID_SUBJECT`, and a `to` that is neither a string nor an array of strings is `INVALID_TO`. An empty string is still accepted for `subject` and `body`. See `docs/guide/nodes.md#send-email`
- **Breaking** for Desktop Notification (all runs, including `aerini-server` and `api`): the notifier is now stopped after 15 seconds and the node fails with `NOTIFY_ERROR`, where a hung `notify-send` or `osascript` blocked it with no limit; the failure text now includes the notifier's stderr. On Linux, `<`, `>` and `&` in Body are escaped so they show as typed; a notification daemon that does not read markup may show the escapes. See `docs/guide/nodes.md#desktop-notification`
- **Breaking** for AI Agent nodes (all runs, including `aerini-server` and `api`): the node makes one model call and no longer loops. It never ran the tools, and fed the model an invented result for each request before asking again, up to Max Iterations paid calls on made-up data. Tool requests now come back in `tool_calls` with `awaiting_tools` true, and `iterations` is always 1; route them with the workflow (for example a Switch on the tool name). Max Iterations is accepted and ignored. A Tools value that is not a JSON array of named tools now fails with `INVALID_TOOLS`, where it used to run with no tools and no warning.
- **Breaking** for AI Memory `append` and `write` with a role other than `user`, `assistant` or `system` (all runs, including `aerini-server` and `api`): the node now fails with `INVALID_ROLE`, where the message was stored and the AI provider refused it on a later read. A message over 4 MiB fails with `CONTENT_TOO_LARGE`.
- **Breaking** for workflows that use an edge's `on_failure` route (all runs, including `aerini-server` and `api`): the target now runs after the node that routes to it in every case, where one that sorted earlier was skipped even though the route fired. A node reached only through `on_failure` is no longer a starting node, so it no longer runs on every run, and an `on_failure` that points back at a node running before it fails the run with `CycleDetected`. Inside a Loop, an `on_failure` target now belongs to the loop body with the node that routes to it, so it runs per iteration, where it used to abort the loop as "outside the body". A schedule's trigger is now found the same way. See [Workflow File Format](docs/reference/workflow-file-format.md)
- **Breaking** for Database Query results (all runs, including `aerini-server` and `api`): a query returning more than 100,000 rows now fails with `ROW_LIMIT_EXCEEDED` instead of loading them all into memory. Add a `LIMIT`.
- **Breaking** for MySQL queries with double-quoted string literals (all runs, including `aerini-server` and `api`): they are now refused like single-quoted ones, because MySQL reads double quotes as strings. Use `?` placeholders; quote identifiers with backticks.
- **Breaking** for a Loop placed inside another Loop's body (all runs, including `aerini-server` and `api`): the run now fails with a message naming both nodes. The inner Loop used to run one pass with the first item and never repeat, so the rest of its array was silently skipped. Put the inner Loop in a separate workflow, or flatten the data first.
- **Breaking** for Loop nodes whose body returns very large results (all runs, including `aerini-server` and `api`): `all_results` is now limited to 256 MB serialized, and the Loop fails with a message naming the iteration where it passed that, instead of using memory until the process is killed.
- **Breaking** for Image Generation (all runs, including `aerini-server` and `api`): an image that cannot be downloaded now fails the node. Flux and ComfyUI used to return an error page as a PNG when the download answered `403`, `404` or a server error, and ComfyUI returned the images it could fetch and logged the rest. The download is tried up to three times for a network error, `408`, `429` or `5xx`; the failure is `DOWNLOAD_ERROR` with the HTTP status and is never retried by the scheduler.
- **Breaking** for Image Generation nodes with no `provider` or one that is not listed (all runs, including `aerini-server` and `api`): the node now fails with `MISSING_PROVIDER` or `UNKNOWN_PROVIDER`, naming the valid values, before it asks for a prompt or key. A missing provider used to run as `gpt_image_1`.
- **Breaking** for Image Generation with GPT Image and `n` above 1 (all runs, including `aerini-server` and `api`): the node sends one request per image and merges the results, so one response no longer risks the 10 MB limit but `n` images take about `n` times as long and count as `n` requests. Some may fail while others succeed (the log says so). A reference image that is empty or not valid base64 now fails with `INVALID_REFERENCE_IMAGE` before anything is sent; it used to be skipped while the call was still billed. A response over 10 MB fails with `RESPONSE_TOO_LARGE` (lower Size or Quality) instead of `PARSE_ERROR`.
- **Breaking** for Image Generation with Nano Banana (all runs, including `aerini-server` and `api`): `source` and the file names now use the configured provider (`nano_banana` or `imagen4`); `source` was always `imagen4`. Gemini replies that carry no image now fail with `PROMPT_BLOCKED`, `IMAGE_BLOCKED` or `NO_IMAGE_RETURNED`, naming the reason and any text the model returned, where they were `EMPTY_RESPONSE`. See `docs/guide/nodes.md#image-generation`
- Image Generation: an OpenAI `429` with `insufficient_quota` (credit or spending limit used up) now fails with `INSUFFICIENT_QUOTA` and is not retried as a rate limit; `moderation_blocked` is reported as `CONTENT_POLICY_VIOLATION`. A Flux job moderated by BFL (`Request Moderated`, `Content Moderated`) also ends as `CONTENT_POLICY_VIOLATION` and stops the remaining `n` images. ComfyUI now skips preview images when the workflow also saves images, and a ComfyUI HTTP 400 is `VALIDATION_ERROR` (was `API_ERROR`).
- Retries: with a retry policy turned on, a `502`, `503` or `504` (and an overloaded `529`) is now retried for calls where a repeat creates nothing: AI Prompt and AI Agent model calls, Stripe Create Payment Intent (the same idempotency key goes with every attempt) and Google Sheets Get Values. The failure code is `UPSTREAM_UNAVAILABLE`. A `500` is never retried, and sends, creates and image-generation jobs (Slack, Telegram, Discord, SendGrid, GitHub, Notion, Google Sheets Append Row, Flux, OpenAI Images, Nano Banana, A1111, ComfyUI) still retry only a `429`, because a gateway often answers after the service already did the work. See [Nodes Reference](docs/guide/nodes.md)
- **Breaking** for workflows that have a typed field set to a value that cannot be read (all runs, including `aerini-server` and `api`): a number or true/false field holding text such as `abc` now fails the node with an unrecoverable `INVALID_CONFIG` naming the field, where it used to fall back to the default without a word. This covers Delay Duration, Wait Duration, Shell and Code Timeout, Schedule interval, Loop Max Iterations, JSON Index, Text Splitter Chunk Size and Overlap, Variables Persist, Webhook Timeout and Validate Timestamp, AI Prompt and AI Agent temperature, token and iteration limits, AI Memory limits and Include Files, Redis Expire, Image Generation size, steps, count, scale and timeout, Send Email HTML, and S3 presign Expiry. A blank field still uses the default, and range limits still apply to valid values. The strictness matters most for flags like Validate Timestamp, which used to switch replay protection off silently. See `docs/guide/nodes.md`
- **Breaking** for Shell Command and Code (JS) nodes that write a very large amount of output (all runs, including `aerini-server` and `api`): a command or script that writes more than 256 MB to one of stdout or stderr is now stopped and fails with an unrecoverable `OUTPUT_FLOOD`, instead of running at full speed until its timeout. Output beyond the 10 MB kept per stream is still discarded as before; only a stream that exceeds 256 MB is affected. Redirect large output to a file.
- Code (JS): the error message for a failed run now shows only the last few KB of stderr, with URL passwords, `--password`-style flags and similar secrets masked, the same as Shell Command. It used to include up to 10 MB of stderr unmasked.
- **Breaking** for If / Condition nodes that use `contains` (all runs, including `aerini-server` and `api`): `contains` now ignores case, like `==` and `!=` in the same node, so `Error contains error` is true where it used to be false. Switch still matches exactly.
- **Breaking** for Wait nodes in `condition` mode: a field that is missing or null no longer matches, so a blank Expected no longer routes a missing field to **Done**; it leaves through **Timed out**. Expected also compares loosely against numbers and booleans, so `"200"` matches `200` and `"true"` matches `true`.
- **Breaking** for workflows that read an unrelated node's output out of a Merge result (all runs, including `aerini-server` and `api`): Merge now returns only the outputs of the nodes wired into it whose connection fired, where it used to return every output produced so far in the run. A node on a branch that was not taken, a failed or skipped node, and a node that is not connected to the Merge no longer appear in the `object` keys or the `array` values, so an `array` index that counted an unrelated node now points at a different value. Wire that node into the Merge, or read its output directly with an expression such as `{{NodeName.output}}`. None of the shipped examples are affected. See [Nodes Reference](docs/guide/nodes.md#merge)
- **Breaking** for muscle memory (desktop app): dragging from either end of a wire no longer picks it up and disconnects it on release. Drag from a wired input, or click the wire and drag the ring on its input end, to move it to another input; dropping anywhere else cancels, and `Esc` cancels mid-drag. Dragging from an output always starts a new wire. To disconnect a wire, click it and press `Del`, or right-click it. A moved wire can be undone with `Ctrl+Z`. See [Keyboard shortcuts](docs/guide/keyboard-shortcuts.md)
- **Breaking** for workflows that wire several sources into one input (all runs, including `aerini-server` and `api`): an input port now accepts one connection unless it is multi-input, and Merge's input is the only multi-input port built in. A workflow that breaks this fails with `PortArityViolation` before any node runs, where it used to run. The desktop canvas already refused a second wire, so only imported, hand-written, AI-generated, or API-submitted workflows are affected; none of the shipped examples are. Route the wires through a Merge node instead. The desktop app opens such a file with every connection intact, marks the input in red, and warns once. See [Workflow File Format](docs/reference/workflow-file-format.md#input-port-arity)
- Canvas (desktop): ports now respond to drags rather than presses. Nothing happens until the pointer moves a few pixels, so clicking an output or an empty input no longer opens the node search; dropping a wire on empty canvas still does. Drag from an empty input to wire backwards to an output (or to a new node), hold `Ctrl`/`Cmd` while dragging from an output to move every wire leaving it onto another output as one undo step, and drop a wire on an input that already has one to replace it, with one `Ctrl+Z` to undo and a notice naming the replaced source; before, the drop did nothing. ### Security
- Database (SQL): the Query operation's read-only check could be bypassed on Postgres with a `$tag$` dollar-quoted string hiding a data-modifying `WITH` clause, and on MySQL with `--`, `#` or `/*! */` comments hiding `INTO OUTFILE`. It now rejects those constructs, `SELECT ... INTO`, a second statement after `;`, and a backslash inside a quoted literal. Valid read-only queries that avoid them are unaffected.
- Database (SQLite): Execute now refuses `ATTACH`, `DETACH` and `VACUUM INTO`. A bound parameter could pass any path to them, past the `.db` extension rule and the sandbox folder.
- Database (SQLite): a network path such as `//host/share/x.db` is refused as Database Path, so opening it can no longer start an outbound network login on Windows.
- SSRF protection: HTTP Request, AI Prompt, AI Agent, Image Generation, Social Upload and the integration nodes (Slack, GitHub, Stripe, Telegram, Discord, Notion, Google Sheets, SendGrid, OAuth sign-in) now check the address again when they connect, so a hostname that resolved to a public address during the early check can no longer resolve to a private, loopback or cloud-metadata address for the connection itself (DNS rebinding). A name with any blocked address is refused, an IP-address redirect to a blocked range is refused, and the failure is `SSRF_BLOCKED` and is not retried. These nodes now ignore system proxy settings, since a proxy resolves the target itself; **Breaking** for networks that require a proxy: set `AERINI_ALLOW_SYSTEM_PROXY=1` to keep using it (only the early check applies then). Redis, Send Email and S3 Storage (R2 and MinIO) get the same check, listed next; Plugin connections get the same treatment, listed below; Postgres and MySQL are unchanged and still need an egress firewall. See [Security](docs/guide/security.md#ssrf-protection)
- SSRF protection: Redis, Send Email (SMTP) and S3 Storage with an R2 or MinIO endpoint now look the host name up once when they connect and dial only an address that passed the filter, so a name that was public during the early check can no longer resolve to a private, loopback or cloud-metadata address for the connection itself. TLS (`rediss://`, SMTP STARTTLS or SSL, S3 over HTTPS) still checks the original host name, so certificate checks are unchanged. **Breaking** in two ways (all runs, including `aerini-server` and `api`): a hostname whose second lookup returns a blocked address now fails at connect (Send Email with `SSRF_BLOCKED`, unrecoverable; Redis and S3 with a connection error that names the block) where it used to connect, and Send Email now tries each validated address with a TCP connection of up to 5 seconds before the SMTP handshake, so a server address that does not answer adds up to 5 seconds before the next is tried. The `aws` S3 provider is unchanged, it takes no user-supplied URL. See [Security](docs/guide/security.md#ssrf-protection)
- SSRF protection: `.wasm` plugin outbound HTTP (action and trigger plugins) now looks the host up once, refuses it if any address is blocked, and connects to a validated address while TLS still checks the original host name, so a name that passed the check can no longer resolve to a private, loopback or cloud-metadata address for the connection itself. A redirect the plugin follows is a new request and is checked again, and a lookup that takes longer than 10 seconds is refused. No change for plugins that call public hosts. See [Security](docs/guide/security.md#ssrf-protection)
- SSRF protection, known limit: Postgres and MySQL connections are still checked only before they connect. The database library uses one host value both as the address to dial and as the name for TLS verification and server-name indication, so dialling a validated IP would break `verify-full` and hosts that route by server name. With `sslmode=verify-full` (Postgres) or `ssl-mode=VERIFY_IDENTITY` (MySQL) a rebound internal address fails the TLS handshake before credentials or queries are sent; the other modes do not check the name. A host-level egress firewall closes the rest; see [Security](docs/guide/security.md#ssrf-protection) and `SECURITY.md`
- Desktop app: approving the confirmation shown before running a Shell Command, Code, Database or plugin node no longer carries over to a changed node. The approval used to be remembered by workflow and node id alone, so after you approved a workflow, editing one of those nodes' settings, re-importing or reloading a modified file with the same ids, or restoring an older version ran the new settings with no prompt. It is now tied to each node's type, settings, saved credential and enabled state, so any change to one of them asks again, while an unchanged workflow still asks once per session. Only a hash of the settings is kept, never the values. Moving or renaming a node does not ask again. See [Nodes Reference](docs/guide/nodes.md#shell-command)
- Desktop app: **Replay** in run history ran the whole workflow, including Shell Command, Code, Database and plugin nodes, without the confirmation that Run, Run this node and a node's Test button show. It now asks first, like they do. See [Nodes Reference](docs/guide/nodes.md#shell-command)
- Desktop app: the confirmation shown before running a Shell Command, Code, Database or plugin node now names each node's type next to its name, so a workflow file can no longer hide one of these nodes behind a harmless-looking name such as "Weather lookup".
- Social Upload: a file's `mime_type` containing line breaks or other control characters is now replaced with `application/octet-stream` instead of being copied into the YouTube upload request, where it could add extra headers to the file part.
- Desktop app: the Summary tab of a run result now escapes a node's type name before showing it, so a workflow file with a crafted node type can no longer inject markup into the results panel.
- Desktop app: the content security policy now also sets `object-src 'none'`, `base-uri 'self'` and `form-action 'self'`. Browsers do not apply `default-src` to `base-uri` or `form-action`, so injected markup could previously add a `<base>` tag or submit a form to another origin. The app itself uses none of these, so nothing changes in normal use.
- `aerini-server` (`api`): the public widget routes (`POST /api/widget/:workflow_id/trigger` and `mint-token`) no longer return internal error text to unauthenticated callers. A database failure, a corrupt trigger row, or a failed relay call used to put SQL or parser messages, or the loopback URL and port of the workflow's Webhook listener, in the response body; they now return a generic message (`internal server error`, or the existing "could not reach the workflow's webhook listener" text) and log the detail server-side.
- `aerini-server` (`api`): with `--trusted-proxy-count` set, only the first `X-Forwarded-For` header line was read, so a proxy that appends its own line instead of extending the client's let a client choose the IP used by the per-IP rate limits. All header lines are now read as one list, and the Nth entry from the right is used as before. Single-line deployments see no change.
- `aerini-server` (`api`): a token restricted by the per-token workflow ACL could still list, read, delete, run, create or overwrite any workflow, and use the server-wide credential routes, limited only by its `read`/`write` scope. Those routes now enforce the ACL; see Changed above.
- `aerini-server`: `--trusted-proxy-count` picked the wrong `X-Forwarded-For` entry, one position too far left, so a client could put its own address at the front of the header and have that used as its IP by the per-IP rate limits (including the widget trigger and `mint-token` limits) and the status page. The Nth entry from the right is now used, as each trusted proxy appends its peer's address. Deployments that already matched their proxy count to their topology see no change for well-formed requests.
- `aerini-server`: a token whose stored expiry cannot be parsed is now rejected instead of never expiring.
- Debug tab: the node id fragment shown in each log line is now HTML-escaped before being inserted into the panel, matching the message text next to it. Verified exploitable: node ids are taken as-is from imported workflow JSON with no validation, so a crafted `id` value could inject markup into the Debug tab once a log entry referenced that node
- Embeddable chat widget (`aerini-widget.js`): session-id generation now tries `crypto.getRandomValues()` before falling back to `Math.random()` for the last `data-session-id` (CWE-338) — closes the gap between `crypto.randomUUID()`, tried first, and the previous direct-to-`Math.random()` fallback. The session id is stored in `localStorage` and sent to the target workflow's Webhook trigger as `session_id`, where it commonly keys per-visitor state (e.g. an AI Memory node, as in `examples/Chatbot + AI Memory + Widget.md`); a `Math.random()`-derived id is predictable enough that another visitor could guess it and inject messages into someone else's conversation thread on a browser/runtime that lacks `crypto.randomUUID` but still has the older, more widely supported `crypto.getRandomValues`
- Plugins: the plugin inspection step now checks a plugin's signature before compiling it or running its code, as loading already did; a file whose signature sidecar is invalid is rejected and shows a load error in Settings. Trigger plugins' `describe()`/`execute()` calls are now also stopped by a CPU deadline, so a guest that never yields cannot hang them
- Plugins: a trigger plugin whose `events()` call or event stream spins without yielding can no longer hold a runtime thread forever or ignore the job's stop. A running trigger now yields to the runtime about once a second, and one that goes about 30 seconds with no WASI or HTTP call and no delivered event is stopped and reported as a trigger error; a trigger that is simply idle between events is not affected. See `docs/development/plugin-authoring.md#trigger-plugins`
- Shell Command: the command line written to the run log now redacts an `Authorization` header value written in single quotes (`-H 'Authorization: Bearer ...'`) or without quotes. Only the double-quoted form was redacted before, so a token in a single-quoted header was saved in the run log in plain text. The closing quote after a redacted double-quoted header is also kept now, so the logged command reads as it was written. Run logs saved earlier are not rewritten; review them if a workflow used the single-quoted form.
- File and Save to Folder (all runs with `--file-sandbox-dir`): a symlink inside the sandbox that points nowhere could be used to create a file outside it, because a write through a missing link target creates the target. Such links are now refused, as are Windows UNC paths. A symlinked subfolder in Save to Folder was never checked against the sandbox and could send files outside it; every subfolder is now resolved and checked, and a sandbox directory that cannot be resolved refuses the run instead of lifting the restriction. Both nodes share one path check.

### Planned (v0.5)
- JSON node: **Source Node** becomes required (see Deprecated above)
- Sub-workflows
- More trigger types (file watch, database poll)
- Workflow bundle import (restore from an `aerini-backup-*.zip`)

- Dependencies: `wasmtime`/`wasmtime-wasi`/`wasmtime-wasi-http` 49.0.1 → 49.0.2 (RUSTSEC-2026-0320, RUSTSEC-2026-0321, RUSTSEC-2026-0322, RUSTSEC-2026-0323, RUSTSEC-2026-0324, RUSTSEC-2026-0325, RUSTSEC-2026-0326, RUSTSEC-2026-0327 — a native stack buffer overflow from an unvalidated async-lifted callback result count, GC heap corruption from mis-typed tag imports and from missing rooting across `try_call`, a host panic from a pre-epoch filesystem timestamp on WASI 0.3, a host panic from a zero `wasi:http` timeout, excess host memory when a guest has no stdio, fuel bypassed by WASI preview 0 `poll_oneoff`, and uninitialized padding copied into guest memory by `fd_readdir`).
