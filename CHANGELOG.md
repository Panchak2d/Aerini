## [Unreleased]

### Added
- Releases: each release now publishes `aerini-server` for x86-64 Linux as a static build (`aerini-server_<version>_x86_64-unknown-linux-musl.tar.gz` with a `.sha256` file), listed under its own heading in the release notes. Export for Server (Linux): when `aerini-server` is not in the unzipped folder, `install.sh` now downloads the release that matches the exporting app's version, checks its checksum, and installs it, so no Rust is needed on x86-64 Linux. A program already in the folder is still used first. On another architecture it stops with the manual steps
- Docs: [Server Deployment](docs/operations/server-deploy.md) gains a TLS reverse-proxy recipe (Caddy, with an nginx variant), ufw firewall steps, a backup and restore procedure for the data volume, and a Compose file for the published image; the `docker run` example now sets `--restart unless-stopped`. [Known Issues](docs/known-issues.md) gains a list of planned work and open questions, and the docs home links to it. The roadmap adds v0.4.5 (AI node hardening) and three v0.5 AI Agent items
- Examples: a new **AI Agent Loop** example, `examples/AI_Agent_Loop.aerini` with a walkthrough, shows an AI Agent that keeps going until it is done. It runs in a Loop over a list whose length is the turn budget, asks for one tool per turn, and the workflow checks and runs each tool and hands the result back; **Stop When** ends the Loop when the agent answers or a request is rejected. Drag the file onto the canvas to import it, then pick an API key for the AI Agent. The pattern was tested on Gemini; other providers are untested in a Loop. There is no token budget or time limit, and the node still does not run tools itself. The Nodes Reference gains a short subsection, "Bounded agent in a Loop", and its router note now points to it
- Loop: a new optional **Stop When** setting (`stop_when`) ends a loop early. It is checked before every item, including the first, and when it resolves to true the loop continues from Done. Empty, `false` (any case), `0` and `null` count as false; anything else is true. A reference to a node that has not run yet is empty, so the first item always runs, and from then on it can read the previous item's result, such as `{{Agent.output.finished}}` or `{{$vars.stop}}`. It can only shorten the loop, so Max Iterations and the array's length still apply. The Done output gains `stopped_early` and `stop_reason` (`stop_when` or null), and when Stop When ends the loop `total` and `items` hold only the items that ran. A list or an object in the field fails the node with `INVALID_STOP_WHEN`. Left blank, nothing changes
- AI Agent (desktop): **Tools** is now a form. Each tool is a card with a name, a description and typed parameters (string, number, integer or boolean, with a description, a Required box and, for a string, allowed values), problems such as a missing or repeated name are shown next to the field before you run, and a line under the list gives the Switch settings (`tool_calls.0.tool` and one case per tool name) that route each tool. It writes the same JSON as before, so saved workflows are unchanged, with each tool's `parameters` saved as a closed object (`additionalProperties` set to `false`). **Edit as JSON** switches to the raw text at any time, and a list the form cannot show without losing something (an expression, nested parameters, `input_schema`, the OpenAI function form) opens as raw JSON and is left exactly as written. Plugin nodes can use it on a string field with `"x-aerini-tool-builder": true`
- Examples: a new **AI Agent Router** example, `examples/AI_Agent_Router.aerini` with a walkthrough, shows how to act on an AI Agent's tool requests: check them with an If on `tool_calls_valid`, route them with a Switch, run the tool, and let a second AI Agent answer from the result. Drag the file onto the canvas to import it, then pick an API key for each AI Agent. The Nodes Reference gains a short note on the pattern and its limits
- AI Agent: three new settings let a conversation continue across nodes. **Return Messages** (`return_messages`, off by default) puts the conversation so far in a new `messages` output, as `{provider, items}` with the provider's own messages; Anthropic's reasoning and search blocks and Gemini's thought signatures are kept untouched, and an OpenAI-compatible turn keeps its text, refusal and tool requests. **Messages** (`messages`) takes that output from an earlier AI Agent, or a list of `{role, content}` turns such as AI Memory returns, and **Tool Results** (`tool_results`, a list of `{id, tool, content, is_error}`) answers the tools the earlier run asked for, so the model carries on from them. Every request must be answered exactly once (`TOOL_RESULTS_MISMATCH`), a result over 64 KiB is cut with a visible marker, a transcript over 4 MiB fails with `MESSAGES_TOO_LARGE`, one from another provider with `MESSAGES_PROVIDER_MISMATCH`, and `system` or `developer` roles in Messages fail with `INVALID_MESSAGES`, so wired-in data cannot add instructions. `messages` is `null` unless requested, and when a tool request was cut off at Max Tokens. With Return Messages on, an Anthropic reply paused mid-search returns its transcript instead of failing with `SEARCH_PAUSED`, and passing it back resumes the search. Nothing changes without these settings. See [Continuing a conversation](docs/guide/nodes.md#ai-agent)
- AI Agent: a new **Web Search** setting (`web_search`) lets the model search the web with its provider's own search inside the same call: Anthropic's `web_search` server tool, Google Search for Gemini, and OpenAI's search model (`gpt-5-search-api`, the default when Model is blank). **Web Search Max Uses** (`web_search_max_uses`, default 5) and **Web Search Domains** (`web_search_domains`) cap and restrict Anthropic's searches. The output gains `search_queries`, `sources` (`{title, url}`) and, for Gemini, `search_suggestions`; all are empty when search is off. Local servers, an OpenAI model that is not a search model, Anthropic together with a Response Schema, and Gemini together with Tools fail with `INVALID_WEB_SEARCH` before any request instead of quietly not searching. An Anthropic reply paused mid-search fails with `SEARCH_PAUSED` when it has no text yet. Search results are untrusted web content and each search is billed by the provider
- AI Agent: a new **Effort** setting (`effort`) sets how hard the model thinks: `output_config.effort` for Anthropic, `thinkingConfig.thinkingLevel` for Gemini and `reasoning_effort` for OpenAI-compatible and local servers. A level the provider has no name for fails with `INVALID_EFFORT`; a level the chosen model rejects comes back as the provider's `API_ERROR`. `default` leaves the provider's own setting, so existing workflows are unchanged
- AI Agent: a new **Response Schema** setting (`response_schema`) makes the model answer in JSON that follows a JSON Schema you write. It is sent in each provider's own structured-output setting, and the reply comes back parsed in `structured`, with `structured_valid` and `structured_error` telling a workflow whether it fits, because a server can accept the setting without enforcing it. A reply that does not fit, including one cut off at Max Tokens, does not fail the node. Text that is not a JSON object schema fails the node with `INVALID_RESPONSE_SCHEMA` before any request; for Anthropic and the hosted OpenAI API the node also checks that every object sets `additionalProperties` to `false` (and, for OpenAI, lists every property in `required`) and names the place in the schema that does not. Without a schema nothing changes: `structured` is `null` and `structured_valid` is false
- AI Agent: three new settings control how the model uses tools. **Tool Choice** (`tool_choice`: `auto`, `required` or `none`) lets the model decide, forces it to ask for a tool, or keeps it to text; **Single Tool Call** (`single_tool_call`) limits a reply to one tool request; **Strict Tools** (`strict_tools`) holds the arguments to each tool's `parameters` schema. They map to each provider's own request fields. A setting a provider cannot honor, such as `required` with Anthropic (current Claude models accept only `auto` and `none`) or either of the other two with Gemini, fails the node with `INVALID_TOOL_CONTROLS` instead of being ignored. With `required`, a reply that asks for no tool is noted in `reasoning`. All three are off or `auto` by default, so existing workflows behave as before
- AI Agent: Anthropic models now receive the node's tools and return their tool requests in `tool_calls`, in the same shape as OpenAI-compatible and Gemini models, so one Switch on `tool_calls.0.tool` works for every provider. Anthropic's `input_schema` is accepted as another spelling of `parameters`, and a reply cut off at Max Tokens while asking for a tool is flagged in `reasoning`
- Local models (desktop): **Pull model** and **Delete model** buttons appear under **Fetch Models** on AI Prompt and AI Agent, and in the Credentials panel's Advanced section, once Aerini sees that the Base URL points at an Ollama server. A pull shows a progress bar with speed and time left and can be cancelled; closing the panel stops it, and pulling again continues. A server that isn't on this computer asks you to confirm first. Aerini only downloads or deletes a model when you click, never while a workflow runs
- Chat (desktop): the banner above the messages now also flags an AI Prompt or AI Agent after the Webhook that has no prompt, and an Output that would show an AI node's whole result as raw JSON, each with a one-click fix. New **Chat bot template** button on an empty canvas adds a ready-to-wire Webhook, AI Prompt and Output workflow, and a [Build a Chat Bot](docs/guide/chat-bot.md) guide explains building one by hand
- Chat (desktop): a Stop button replaces Send while a reply is pending and cancels only that reply; the workflow keeps running, so the next message works without a restart
- Canvas (desktop): scroll over the minimap to zoom the canvas, and hold `Ctrl` (`Cmd` on macOS, or pinch on a trackpad) while scrolling to zoom in on the minimap itself, keeping the spot under your pointer fixed. Double-click a node on the minimap to select it on the canvas and bring it to the centre; double-click empty space on the minimap to reset its zoom and fit the whole workflow on screen
- Canvas (desktop): once the minimap is zoomed in, hold `Ctrl` (`Cmd` on macOS) and drag it, or drag with the middle mouse button, to pan it and reach any part of the workflow. A plain drag still moves the canvas view, and holding the view box against the edge of a zoomed-in minimap scrolls it
- Canvas (desktop): the minimap can be resized. Drag the grip in its top-left corner (up and left to enlarge), or focus it and use the arrow keys, `Page Up` / `Page Down`, `Home` and `End`; double-click it or press `Enter` to go back to the default size. The size is remembered between launches and shrinks on its own when the window, the chat panel or the output drawer leaves too little room
- Canvas (desktop): hover a node on the minimap to see its name and status. When any node has an error, a badge in the minimap's bottom-left corner shows the count; click it to jump to the next error (`Shift`-click for the previous one)
- AI Agent: the output now includes `model`, `provider`, `input_tokens` and `output_tokens`, the same fields AI Prompt returns. Each entry in `tool_calls` gains `arguments_valid`, `known_tool` and `error`, and the output gains `tool_calls_valid`, so a workflow can check a tool request before acting on it. The arguments are checked against the tool's `parameters` schema and the name against the declared tools; the node still succeeds and returns the request

- Canvas (desktop): wiring a Webhook into an AI Prompt or AI Agent with an empty Prompt (or Goal) fills in the chat message expression, and wiring an AI Prompt or AI Agent into an Output with an empty Field sets it to the reply field (`content` or `result`). ## [0.4.3] - 2026-10-20

### Added
- `aerini-mcp`: a Model Context Protocol server over stdio, so an AI agent can read the node catalog, check and write workflows, and run them. With `AERINI_URL` and `AERINI_TOKEN` it talks to an `aerini-server api` instance and inherits the token's scope and workflow access list; tools that change the server (`save_workflow`, `delete_workflow`, `start_schedule`, `stop_schedule`) also need the `--allow-write` flag. Built with `--features offline` and run without `AERINI_URL`, it serves the built-in node catalog, validates workflows and writes `.aerini` files for the desktop app, and never runs anything. Run output is cut at 32 KiB by default (`--max-output-bytes`) and marked as untrusted data. Every release publishes `aerini-mcp` (about 4 MB) and `aerini-mcp-offline` (about 47 MB, the offline build) for Linux x86_64 and arm64, macOS Apple Silicon and Windows x64, each with a `.sha256` file. See [MCP Server for AI Agents](docs/operations/mcp.md) and [Building Workflows with an AI Agent](docs/guide/agents.md).
- `aerini-server api`: `GET /api/nodes` lists the node types the server can run, plugins included, with their config schemas and ports, and marks Shell Command, Code and Database nodes `enabled: false` when the server has them switched off. `POST /api/validate-workflow` checks a workflow without saving or running it and returns its errors and warnings: unknown node types, dangling or cyclic edges, two wires into a one-wire port, edges naming ports a node does not have, and empty required fields. Both need only the `read` scope. See the [Server API Reference](docs/operations/server-api-reference.md#node-catalog-and-validation).
- Embedding: `aerini_engine::validation::validate_workflow` (and `validate_workflow_json`) runs those checks against a `NodeRegistry` and returns a `ValidationReport`. A report without errors means no known structural problem, not that the run will succeed.
- `docs/reference/node-catalog.md` and `docs/reference/node-schemas.json` list every built-in node with its config fields, ports and output fields, and `docs/reference/workflow.schema.json` is a JSON Schema for the workflow file. All three are generated from the engine and checked by its tests, so they match the code.
- Embedding: `aerini-engine` has an optional `schema` feature that derives JSON Schema for the workflow file types in `model.rs`. It is off by default.
- `aerini-server restore-key` puts a backed-up credential encryption key back into an `api` data folder (`--key-file`, or standard input; `--keychain` for the OS keychain). The key is checked against the saved credentials first and nothing changes if it does not decrypt them.
- Embedding: `aerini_engine::credential_env` holds the one function that turns a credential ID into its `AERINI_CRED_*` variable name, used by the server export and `aerini-server serve`.
- Embedding: `CredentialStore::restore_key_base64(db_path, key_source, backup)` replaces the stored encryption key with a backup after checking that it decrypts a stored credential. It works on a store that `open` refuses and changes nothing when the key is wrong. The desktop app and `aerini-server` have no restore command; see [Credentials](docs/guide/credentials.md).
- Database: **Password** (`password`) for Postgres, MySQL and Redis takes a saved credential and replaces any password in **Connection URL**, so the secret stays out of the workflow file, exports and version history. A password written in the URL still works
- Database: Execute returns `RETURNING` rows in `rows` on Postgres, SQLite and MariaDB (`INSERT ... RETURNING *`); over 100,000 rows or 32 MiB it keeps what fits, sets `truncated` and logs `RESULT_TRUNCATED`, since the write has already happened. On SQLite, Execute with `RETURNING` used to fail
- Database (Postgres, MySQL): NUMERIC/DECIMAL (exact string), dates and times (ISO 8601 strings), UUID, JSON/JSONB (parsed value) and Postgres enums are returned as values instead of a placeholder

### Changed
- **Breaking** `aerini-server api` no longer changes the permissions of an existing `--data-dir`. A folder it creates is owner-only; an existing folder is left as it is and a start-up warning appears when group or other users can access it.
- **Breaking** `GET /api/events`: a connection limited by the token's workflow ACL or by `?workflow_id=` receives only events that name an allowed workflow. `scheduler-ready` (it carried the server-wide job count) and any event with no workflow are no longer sent to it.
- A run-history listing returns at most 64 MiB of run results per call. Rows past that carry a size marker instead of their result; opening one from the desktop history shows it as too large to list.
- S3 Storage **Secret Access Key**, and **Client Secret** on Google Sheets and Social Upload, now offer the saved-credential dropdown, with **Or enter a value directly** under it for a value typed into the node. A selected credential wins. These fields are masked in run results whichever way they are filled
- **Breaking** `aerini-server serve` reads only the variables listed in `credential_env_vars`; a credential ID missing from it is no longer looked up as `AERINI_CRED_<ID>`. Every name in the mapping must start with `AERINI_CRED_` (letters A-Z, digits and `_` after it), and two IDs that share one variable stop the server at start-up. Server export applies the same name rule to every non-letter, non-digit character, and fails when two credential IDs (such as `a-b` and `a_b`) would share a variable, naming both.
- **Breaking** `aerini-server api` stops at start-up when no unrevoked, unexpired admin token exists, and when the `--token` / `AERINI_TOKEN` value was revoked. Before, a revoked token that was supplied again was ignored without a message and the server ran with no usable admin token. A `--token` the server doesn't know is added as a new admin token with a warning that the older tokens stay active.
- **Breaking** Credential storage format: each secret is now encrypted together with its ID, type and metadata, and a new `enc_version` column and `credential_meta` table record the format and an encrypted key-check value. Credentials saved by earlier versions are rewritten in the new format the first time a workflow reads them, after which an older version of Aerini cannot read them. Back up the data folder before updating if you may go back.
- **Breaking** Aerini stops at start-up with a key-mismatch error when the key it found decrypts none of the saved credentials (`EngineError::KeyMismatch`). Before, it started and every credential failed one at a time.
- **Breaking** (embedding) `CredentialResolver::resolve`, `CredentialStore::retrieve` and `CredentialStore::export_key_base64` return `aerini_engine::executor::SecretString` (`zeroize::Zeroizing<String>`) instead of `String`, and `EngineError` gains `KeyMismatch`. `CreateCredentialRequest` no longer implements `Serialize`.
- **Breaking** Credentials panel: **Edit** no longer loads the saved secret into the window. **Secret Value** is blank ("unchanged") and a blank value keeps the saved secret. The `get_credential_secret` command is removed, `save_credential` takes an `update` flag, and **Fetch Models** for a saved credential goes through the new `list_credential_models` command
- **Breaking** Creating a credential whose ID already exists now fails (`CredentialExists`, `409` from `POST /api/credentials`) instead of overwriting it and resetting its creation time. The server accepts `"update": true` to replace one. Deleting an unknown ID returns not found (`404`)
- **Breaking** (embedding) `aerini_engine::store::CredentialStore::store` is replaced by `create` and `update`, and `EngineError` gains `CredentialInvalid` and `CredentialExists`
- **Breaking** Credential input is validated in the store: ID 1-128 characters of letters, digits, `_` and `-` (existing IDs with other characters stay readable and editable), name up to 256 characters, value up to 65,536 bytes, type one of `api_key`, `bearer`, `basic`, `oauth`, `other`, and `base_url` an `http(s)` URL without a username or password
- **Breaking** Credential key in the OS keychain: each data folder now has its own entry (account `encryption_key:<hash of the folder path>`) instead of one entry shared by every copy of Aerini. A folder that already has credentials copies the shared key into its own entry on first start, after checking it decrypts them, and the shared entry is left in place, so existing installs keep working. A new data folder gets a new key, which an older Aerini build cannot find; downgrading such a folder needs the key restored from a backup
- **Breaking** A saved credential can fill only a node's credential fields (`api_key`, `password`, or a field its node type marks `x-aerini-credential`). A workflow that maps one onto another field, such as `url` or `headers`, now fails that node with `CREDENTIAL_FIELD_NOT_ALLOWED`; before, the mapping overwrote any config field
- **Breaking** A saved credential that exists but cannot be read, or a credential store that cannot be reached, now fails the node. Before, the node ran without the value and could send an unauthenticated request. A credential that no longer exists still only logs a warning
- **Breaking** (embedding) `aerini_engine::model::NodeInput` no longer implements `Serialize` or `Deserialize`, and its `Debug` output omits `input`, `resolved_credentials` and `context`
- **Breaking** Database: **Params** text that is not a JSON array now fails with `INVALID_PARAMS`. It used to be ignored, which ended in a "wrong number of parameters" error or a query that ran without its values
- **Breaking** Export for Server and Export for Docker name the generated service, install folder, Docker image and volume from the workflow name in lowercase letters and digits, with each run of other characters replaced by one hyphen and at most 48 characters (`My Flow!` becomes `my-flow`). Before, capitals, spaces and non-ASCII letters were kept or turned into underscores, which Docker rejects in an image name. A package exported by an older build keeps its old names; installing a new package for the same workflow with `install.sh` creates a second service and folder, so stop and remove the old ones first.
- **Breaking** The `Dockerfile` in an Export for Docker package builds the release tag that matches the desktop app that exported it (`AERINI_REF` defaults to `v<version>`) instead of `main`. A build of Aerini that has no published tag needs `--build-arg AERINI_REF=<branch or tag>`.

### Security
- `POST /api/tokens`: a label with control characters is refused.
- The plugin install, remove and reload commands accept only the plugin folder saved in Settings.
- Run results mask a secret typed into S3 Secret Access Key or a Google Sheets or Social Upload Client Secret, as they already did for `api_key` and `password`, and mask the text of the error a failed run returns (node failure reasons and validation messages), not only the result's outputs, logs and errors.
- `aerini-server serve`: a mapped environment variable that is set but not valid Unicode is reported as unreadable (the node fails) and at start-up, instead of looking unset. The `run_secret` start-up message says whether the stored value is a BLAKE3 hash or the secret in plain text; a 64-character plain-text secret is no longer mistaken for a hash.
- Builds on a platform where the keychain library has no persistent store keep the key in the owner-only key file instead of an in-memory store that is lost at exit. Windows, macOS and Linux builds are unaffected. Such a build logs a warning at start-up saying where the key lives.
- Saved credentials are bound to their ID and type, so a stored secret copied onto another credential, or onto a credential of another type, no longer decrypts. The key is checked against a stored value before any credential is read, so a stale key can no longer be used by mistake.
- The credential cipher (`aes-gcm` `zeroize` feature), the encryption key, decrypted credential values and `CreateCredentialRequest.value` are overwritten when dropped, and `CreateCredentialRequest`'s `Debug` output hides `value`. Copies in node input, HTTP buffers, the process environment and the window are not wiped; see [Known issues](docs/known-issues.md).
- The webview no longer receives saved secrets, and **Backup Encryption Key** asks for confirmation in a native system dialog the window cannot answer. The revealed key hides after 60 seconds or when the panel closes, and the clipboard is cleared 60 seconds after copying it
- Run results mask saved credential values and values typed into `api_key`, `password` or a plugin field marked `x-aerini-credential`, of 8 or more characters in node outputs, logs, error messages and schema warnings, so a node that echoes its input no longer writes a secret into run history
- Input schema validation no longer repeats credential values: a workflow's schema could make the validation message quote the resolved secret, which then reached the run log or the run's error
- Unix: the credential database, the key file's folder and the data folder are created owner-only, not created at the default permissions and tightened afterwards. Windows: the credential database and key files are restricted to your user, the key file before any key bytes are written, and an existing key file is re-restricted on each start
- Database: the Postgres and MySQL address check now covers the host the driver will dial. `?host=`, `?hostaddr=` and `?port=` in a Postgres URL could point the connection at a blocked address (for example `postgres://u@public.example.com/db?host=169.254.169.254`) while the check saw only `public.example.com`. Unix sockets are refused
- Code (JS) with `--code-sandbox`: also blocks importing `tls`, `wasi`, `trace_events`, `node:sqlite` and `node:test`, and removes `process.kill()` and `process.report`. Before, sandboxed code could open raw TLS connections, use SQLite or WASI to reach files, or signal other processes, none of which the existing block list covered
- Server and Docker exports are written to an owner-only file with a random name in the temporary folder, and `save_export_zip` accepts only a file the export commands made in the current session. The temporary file is deleted whether the save succeeds, fails or is cancelled, and a leftover older than an hour is deleted by the next export.
- `install.sh` from a server export sets `umask 077` before it copies the binary, `aerini-server.json` and `.env`, so none of them is readable by other users, not even briefly.
- The plugin folder can only be set through the folder picker (`choose_plugin_dir`); `set_setting` refuses the `plugin_dir` key. A setting key over 256 bytes or a value over 1 MiB is refused.
- Plugin outbound HTTP: each phase (connect, first byte, gap between body chunks) is held to 30 seconds, one request to 60 seconds, and a plugin call still running after 120 seconds is stopped. Before, a plugin could ask for a 10 minute timeout and hold its run for that long.
- Dependencies: `wasmtime`/`wasmtime-wasi`/`wasmtime-wasi-http` 49.0.2 → 49.0.3 (RUSTSEC-2026-0350 to RUSTSEC-2026-0364 — a filesystem sandbox escape when a guest renames symlinks with trailing slashes, a guest `wasi:http` request target that addresses a different host, a host crash from a long request URL, host panics in async component calls, streams and futures, and component handles, now capped at 100,000 live per store). Plugin outbound HTTP also refuses a request target that is not a path before sending it
- Dependencies: `rustls` 0.23.45 → 0.23.46 (RUSTSEC-2026-0346 to RUSTSEC-2026-0349 — TLS secrets in `Debug` output, Brotli certificate decompression allocating up to 1 GiB before authentication, a downgrade to classical key exchange, and buffered data sent to the outer server after an ECH rejection)
- Dependencies: `zip` 8 → 9 in the desktop app (RUSTSEC-2026-0367, RUSTSEC-2026-0368, RUSTSEC-2026-0369 — unsafe symlink and permission handling in archive extraction; Aerini reads plugin packages entry by entry and never calls `extract`). The update check no longer builds the updater's `zip` feature (Tauri v1 bundle support, the only user of `zip` 4); `zip` 8.6.0 stays in the build through `docx-rs`, so those three advisories are listed in `.cargo/audit.toml` and `deny.toml` with the reason, until `docx-rs` moves to `zip` 9

### Fixed
- Desktop Notification on Windows: the PowerShell step failed before showing anything (it could not create the XML document, and it could not read the notification file while Aerini still had it open for writing). The notification file path is also passed in the environment, so a user profile folder with a quote or `$` in its name no longer affects the command (not yet run on a real Windows desktop)
- Code node: a log line `PRECISION` reports integers in the input or context beyond 2^53, which JavaScript rounds. The script now reaches Node.js through a write that the timeout also covers, and a temporary folder with a space or `#` in its path no longer breaks the sandbox loader.
- HTTP Request: a response header value that is not valid UTF-8 is returned (invalid bytes replaced) instead of an empty string.
- Monitor: a slow refresh is no longer overlapped by the next one, and a refresh left over from a previous open of the panel can no longer block the new one.
- Stop: a run that was stopped and then failed on the backend no longer shows an error card, and no longer causes the next run's result to be discarded.
- `POST /api/workflows/:id/run` cancels the run when the client disconnects. Before, the run kept going (and could keep a shell command or request alive) with nobody waiting for the result.
- `--bind` with a bare IPv6 address (`::1`, `::`) failed with "Cannot bind" in `api` and `serve`; the address is now bracketed before binding.
- A run keeps at most 100,000 log entries and 16 KiB per log message, so a runaway node cannot grow a run without bound.
- A panic while the scheduler, plugin file watcher or parallel executor held an internal lock no longer makes every later call panic.
- Database: the error for a Query result over the row or size limit now says to add a `LIMIT`, read in pages, aggregate or select fewer columns; a Redis value over 32 MiB says to store it in smaller pieces.
- Credential key directory: a `.tmp*` file left by a crash between writing the key and renaming it into place (it holds a complete key) is overwritten and removed at the next start once it is 10 minutes old.
- `aerini-server api`: opening the token database adds the `expires_at` column inside one write transaction, so two servers starting together no longer race on it, and a read error is reported instead of treated as "column missing".
- Credentials panel: **Delete** refuses when a workflow could not be read, instead of treating it as not using the credential. Credential commands in the desktop app no longer block the async runtime
- Credential key file and `tokens.key`: created through a temporary file that is flushed before it is renamed into place, under a lock file (`<key file>.lock`) beside it. Two processes starting together on a new data folder could read a key file the other had not finished writing and fail to start, and a crash or power loss right after creation could leave an empty key file that made every saved credential (or every API token) unreadable
- Credential key in the OS keychain: starting two copies of Aerini on the same data folder at once could leave one holding a key the keychain no longer had; a failed read-back no longer deletes the keychain entry, and a key the keychain cannot serve back is saved to the key file instead of being replaced by a different one
- A key file left beside a working keychain entry is removed when it holds the same key, and Aerini stops with an error when the two differ and credentials exist. Before, a stale file could later be used silently and every credential would fail to decrypt. A key file that could not be deleted after migrating to the keychain is now reported instead of logged as migrated
- Opening an older credential database from two processes at once no longer fails with "duplicate column name". Deleted credential data is now overwritten in the database file (`secure_delete`)
- Database: a slow or unreachable Postgres, MySQL or Redis host no longer delays connecting to every other one; only callers of the same connection wait for each other
- Shell Command: a command that fails without writing to stderr no longer ends with an empty `Exit code N: ` message; the error now shows the end of stdout (redacted the same way), or says the command printed no output
- Installing a plugin or a plugin pack reads the source once, checks the staged copy, and renames it into place, the `.wasm` before its `.sig`; a full disk or a closed app no longer leaves a truncated plugin. A staging file left behind is deleted by a later install once it is an hour old.
- A manual run started with a `run_id` that is empty, over 128 bytes or already running now fails instead of replacing the first run's cancel entry, and the entry is removed even when the call is dropped before the run ends.

### Fixed
**Engine and workflows**
- Parallel execution: a Merge after a branching node no longer skips everything after it when an incoming branch was not taken
- Wait: a timeout continues from **Timed out** (falls back to **Done** if unconnected)
- Loops: a node no longer receives a skipped or failed predecessor's output from an earlier iteration. When **Max Iterations** stops a loop early, Done's `items` is cut to the items that ran (**Breaking** if you read the full array there; read the source node)
- Field paths (Switch, Loop, Wait, Output, Text Splitter) read array items by position (`items.0.id`)
- Output: with **Source Node** blank, shows the wired node's output instead of the last node to finish
- JSON: optional **Source Node** limits `stringify`, `extract`, `merge` and `array_get` to one node (`extract` pointers relative to it); no output fails with `SOURCE_NOT_FOUND`
- **Breaking** for Transform: `from: "/"` addresses a key named `""` (RFC 6901), not the whole source; `//a` no longer acts like `/a`
- If / Condition: `a=b contains b` is no longer split at the `=`; an empty side no longer makes `contains` true
- **Breaking** for Set Variable with **Persist**: a failed save fails with `DB_ERROR` (was a log warning). Variable logs show only type and size
- Numeric and boolean settings arriving as text (`"timeout_secs": "5"`) are read instead of ignored across Delay, Wait, Stripe, Shell Command, Loop, Schedule, Webhook, JSON, Variables, Text Splitter, AI and Redis nodes; unreadable text fails (see Changed). Database `allow_raw_sql`/`allow_local` accept only a real boolean
- Schedule (cron): out-of-range values fail at once naming the field; `0 0 29 2 *` finds the next leap day without blocking the scheduler; names only in their own fields; a weekday range ending in `7` includes Sunday; macros are case-insensitive; an oversized **Interval** waits instead of panicking
- Webhook: a text `port` (`"8080"`) is used; ports outside 1024–65535 fail with `INVALID_PORT` (66560 used to wrap to 1024); `path` gets a leading `/`; lowercase `method` matches

**Background runs and plugins**
- A job whose task panicked kept its workflow marked running and its webhook port claimed until restart; both are now freed and the panic logged
- Also fixed: the config panel hides no new fields on older saved nodes; n8n Gmail imports as Send Email and a converted Switch's **Source Node** is the imported id; the toolbar refreshes after importing a workflow; Webhook listener accepts `Header:value` without a space and no longer pre-reserves memory for a declared `Content-Length`; Database pools are capped at 64 per backend; AI Memory database work runs off async threads and a failed prune is reported; `Authorization: Bearer` is case-insensitive, tolerates extra spaces, and an empty one counts as missing; same-named video/audio outputs no longer overwrite each other; `.env.example` ships an empty `AERINI_TOKEN` (32+ characters required)
- Plugin triggers start in background runs (the scheduler never got the plugin directory; desktop uses the Settings folder, `aerini-server` uses `--plugin-dir`); a trigger-capable plugin as the entry node is no longer rejected, and Run executes it once as an ordinary step
- `wasip3` (WASI 0.3) trigger plugins load, and `describe()`/`execute()` run on the async engine with the 30 s limit; an uppercase extension (`Plugin.WASM`) loads at startup; the storage quota counts bytes
- A spinning trigger plugin no longer holds a runtime thread: stopped at 30 s ("plugin ran for 30s without returning and was stopped"), including 30 s without a WASI/HTTP/storage/file-watch call or event (idle ones are unaffected). Starting a trigger gives each file 30 s, stops scanning after 90 s and names skipped files; a failing trigger restarts after a growing pause (5 s doubling to 5 min) and logs the same error at most every 5 minutes
- Plugin and reload commands (desktop, `POST /api/plugins/reload`, `serve` SIGHUP) no longer stall other work while plugins compile

**Shell Command and Code (JS)**
- Timeout, cancellation or workflow timeout kills the command and everything it started on macOS and Linux (own process group); `timeout_secs` also covers reading output, so a background process holding it open no longer outlasts the timeout
- **Breaking** for retry policies on Shell Command timeouts: fails with unrecoverable `TIMEOUT` (the command may have partly run); `timeout_secs` is kept between 1 and 86400
- Output over 10 MB no longer stalls until the timeout: extra output is discarded and `truncated` is `true`. Failure messages show only the end of stderr with secrets masked, now covering `--password x`, `--token x`, `--secret x`, `--passphrase x|=x`, quoted values, curl `-u user:pass`, `--user`, `--proxy-user`, `sshpass -p` and MySQL `-pPASSWORD`, and no longer masking after `mkdir -p`, `ls -p` or `ssh -p`. Masking is pattern-based; a secret in an unfamiliar flag can still show
- Code (JS): `console.log()` no longer fails the node with `PARSE_ERROR`; the result travels on its own marked final stdout line; past 10 MB of printed text the last 10 MB is kept (`truncated` `true`). `process.exit()` before finishing fails with `NO_RESULT`; a result over 10 MB with `RESULT_TOO_LARGE`; `timeout_secs` accepts expressions and is kept between 1 and 60. Stderr's last lines are no longer lost on `process.exit()`, and runaway output stops with `OUTPUT_FLOOD`
- **Breaking** for workflows reading the result envelope from a Code node's `stdout`: it now holds only printed text; read `result`
- `aerini-server` `--code-sandbox` on Linux: Code nodes start again (Node.js 24 aborts under ~1.1 GB of address space). The limit is `--max-code-memory-mb` (default 512) plus 2 GB for startup (4 GB on arm64, not yet measured there)

**Database**

### Security
- **Breaking** for networks that require a proxy: SSRF protection now re-checks the address at connect time (DNS rebinding) for HTTP Request, AI Prompt, AI Agent, Image Generation, Social Upload, and the Slack, GitHub, Stripe, Telegram, Discord, Notion, Google Sheets, SendGrid and OAuth nodes. A name with any blocked address, or an IP redirect to a blocked range, fails with unrecoverable `SSRF_BLOCKED`. These nodes ignore system proxy settings; set `AERINI_ALLOW_SYSTEM_PROXY=1` to keep using one (only the early check applies then)
- **Breaking** for Redis, Send Email and S3 (R2/MinIO): the host is resolved once and only a validated address is dialed (TLS still checks the original name). A name whose second lookup returns a blocked address fails at connect (Send Email: `SSRF_BLOCKED`, unrecoverable). Send Email tries each validated address with a TCP connect of up to 5 s, so an unresponsive address adds up to 5 s before the next. `.wasm` plugin outbound HTTP gets the same treatment, re-checks redirects, and refuses lookups over 10 s
- SSRF known limit: Postgres and MySQL are still checked only before connecting (the driver uses one host value for dialing and TLS names). `sslmode=verify-full` (Postgres) or `ssl-mode=VERIFY_IDENTITY` (MySQL) makes a rebound internal address fail the handshake before credentials are sent; other modes do not. Use a host-level egress firewall (see `SECURITY.md`)
- SSRF filter: blocks AWS's IPv6 metadata address `fd00:ec2::254` even under AllowLocal, and `192.0.0.0/24` (includes Oracle Cloud metadata `192.0.0.192`) under both policies
- Shell Command, and Code (JS) with the sandbox off, no longer inherit `AERINI_*` environment variables (`AERINI_TOKEN` is the admin token, `AERINI_CRED_*` hold credentials, so a write-token workflow author could print them and gain admin access). Other variables are inherited, `aerini-server api` passes `AERINI_*` variables listed in `--allow-env-vars`, and variables in the node's **Env** field always pass. A script that read an `AERINI_*` variable must set it in **Env**
- Shell Command: the logged command line now redacts `Authorization` headers in single quotes or unquoted (only double-quoted was redacted) and keeps the closing quote of redacted double-quoted ones. Run logs saved earlier are not rewritten; review them if a workflow used the single-quoted form
- File, Save to Folder and Database (SQLite) with `--file-sandbox-dir`: a symlink pointing nowhere could create a file or database outside the sandbox (writing through a missing link target creates it). Such links and Windows UNC paths are now refused; every Save to Folder subfolder is resolved and checked (a symlinked one escaped the sandbox); an unresolvable sandbox directory refuses the run; a non-string SQLite sandbox setting fails with `INVALID_PATH` instead of switching the check off. File, Save to Folder and SQLite share one path check, and SQLite opens the checked path (Unix)
- Database (SQL): the Query read-only check was bypassable on Postgres with a `$tag$` dollar-quoted string hiding a data-modifying `WITH`, and on MySQL with `--`, `#` or `/*! */` comments hiding `INTO OUTFILE`. It now rejects those, `SELECT ... INTO`, a second statement after `;`, and a backslash inside a quoted literal
- Database (SQLite): Execute refuses `ATTACH`, `DETACH` and `VACUUM INTO` (a bound parameter could pass any path past the `.db` rule and sandbox); a network path such as `//host/share/x.db` is refused as Database Path (it could start an outbound login on Windows)
- `aerini-server` widget `trigger`: a Webhook node with no secret is refused with `400` (set a secret to keep using the widget). Widget routes cap bodies at 1 MiB. Widget and `mint-token` error responses no longer expose SQL or parser text or the loopback URL and port of the Webhook listener. The relay to the local Webhook listener ignores system proxy settings and does not follow redirects, so the secret cannot reach a proxy or another host
- Webhook (Run Now and background) and OAuth callback: secret and `state` comparisons no longer return early on a length mismatch, so length cannot be probed through timing
- **Breaking** for tokens with workflow grants: the ACL now confines a restricted token on every workflow and credential route (it could previously list, read, delete, run, create or overwrite any workflow, limited only by `read`/`write` scope). See Changed
- `aerini-server`: `--trusted-proxy-count` picked the `X-Forwarded-For` entry one position too far left, letting a client put its own address first and choose the IP used by per-IP rate limits (including widget `trigger`/`mint-token`) and the status page; the Nth entry from the right is used now. All header lines are read as one list (a proxy that appended its own line let a client choose the IP). Correctly configured single-line deployments see no change
- `aerini-server`: a token whose stored expiry cannot be parsed is rejected instead of never expiring
- Plugins: the 64 MiB memory limit covers all of a plugin's memories together (was per memory) and tables are limited to 100,000 elements; with `--file-sandbox-dir`, `fs-watch` stays inside it for action and trigger plugins; inspection checks the signature before compiling or running code (an invalid signature sidecar is rejected with a load error in Settings); trigger `describe()`/`execute()` are stopped by a CPU deadline; a trigger whose `events()` or event stream spins can no longer hold a runtime thread or ignore a stop
- Desktop: installing a single plugin writes the bytes whose signature was checked (was a second copy of the file); the plugin trust file is written to a temporary file and renamed into place so an interrupted write cannot truncate it
- Desktop: the Shell Command, Code, Database and plugin confirmation is now tied to each node's type, settings, saved credential and enabled state (a hash of settings, never values), so editing, re-importing or reloading a modified file with the same ids, or restoring an older version, asks again (it was remembered by workflow and node id alone). Unchanged workflows still ask once per session; moving or renaming a node does not ask again. The confirmation names each node's type so a harmless-looking name cannot hide one. **Replay** in run history now asks first, like Run, Run this node and Test
- Desktop: the temporary file for video and audio output is stored in a directory only the current user can use, named by a hash of its contents, and replaces a file or symlink at that path instead of writing through it (it used a fixed, guessable shared path, `/tmp/aerini_media` on Linux, where another local user could plant a symlink; on Windows `C:name` wrote outside the temp path). File names are reduced to their last segment with unusual characters replaced by `_`
- Unix: on startup an existing key file (`.cred.key` or `aerini.key`; `tokens.key` for `aerini-server api`) readable by other users is restricted to its owner (a file Aerini does not own logs a warning), and the credential database is created owner-only. Credential key material in memory is wiped when no longer needed. Windows: the owner-only ACL setup reads the user record from a correctly aligned buffer (removes a latent undefined-behavior hazard; permissions unchanged)
- Desktop XSS and CSP: the Summary tab and the Debug tab's node id fragment escape values from imported workflow JSON (node ids are unvalidated; a crafted `id` could inject markup, verified exploitable in the Debug tab). The content security policy adds `object-src 'none'`, `base-uri 'self'` and `form-action 'self'` (browsers do not apply `default-src` to `base-uri` or `form-action`); the app uses none of these
- Social Upload: a `mime_type` with line breaks or control characters is replaced with `application/octet-stream` instead of being copied into the YouTube request, where it could add extra headers
- Embedded chat widget (`aerini-widget.js`): session-id generation tries `crypto.getRandomValues()` before falling back to `Math.random()` (CWE-338). The id keys per-visitor state such as an AI Memory node, so a guessable one let another visitor inject messages into someone's conversation on a browser with `getRandomValues` but no `randomUUID`
- Dependencies: `quinn-proto` 0.11.16 → 0.11.19 (RUSTSEC-2026-0338, RUSTSEC-2026-0339, RUSTSEC-2026-0340, RUSTSEC-2026-0341, RUSTSEC-2026-0342: a remote peer could panic the QUIC stack with zero-length stream frames or an out-of-range minimum ACK delay, and bypass stream-reassembly, datagram-buffer and connection-ID-retirement limits). Reaches the build only through `reqwest`; `Cargo.lock` only

- Widget (`aerini-widget.js`): the auto-generated session id no longer falls back to `Math.random()` when the browser has no Web Crypto API (CodeQL `js/insecure-randomness`, CWE-338). - Dependencies: `wasmtime`/`wasmtime-wasi`/`wasmtime-wasi-http` 46.0.3 → 49.0.1 (RUSTSEC-2026-0313, RUSTSEC-2026-0314, RUSTSEC-2026-0316, GHSA-m63x-6p34-q65x — guest-driven host memory exhaustion through an outgoing HTTP body write, a host panic from an out-of-range filesystem datetime, and fuel not charged for dynamic record lifting or for callees of `call_ref`). No 46.x release carries the fixes; only 48.0.3+, 49.0.1+ and 36.0.16 do. Plugin outbound HTTP is still SSRF-filtered by the same policy for both action and trigger plugins
- Dependencies: `wasmtime`/`wasmtime-wasi`/`wasmtime-wasi-http` 49.0.1 → 49.0.2 (RUSTSEC-2026-0320, RUSTSEC-2026-0321, RUSTSEC-2026-0322, RUSTSEC-2026-0323, RUSTSEC-2026-0324, RUSTSEC-2026-0325, RUSTSEC-2026-0326, RUSTSEC-2026-0327 — a native stack buffer overflow from an unvalidated async-lifted callback result count, GC heap corruption from mis-typed tag imports and from missing rooting across `try_call`, a host panic from a pre-epoch filesystem timestamp on WASI 0.3, a host panic from a zero `wasi:http` timeout, excess host memory when a guest has no stdio, fuel bypassed by WASI preview 0 `poll_oneoff`, and uninitialized padding copied into guest memory by `fd_readdir`).
